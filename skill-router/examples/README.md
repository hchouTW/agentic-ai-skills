# skill-router Examples

Canonical worked examples in one of eight archetypes - see `task-authoring`'s
[references/example-authoring.md](../../task-authoring/references/example-authoring.md)
for the archetype-selection guide and how these are generated and validated
(requires `task-authoring` installed alongside this skill).

| Example | Archetype | Scenario | One-line takeaway |
|---|---|---|---|
| [01-adding-a-routing-rule-without-overlap.md](01-adding-a-routing-rule-without-overlap.md) | Contrast | Adding a new routing rule to the table without creating overlap or ambiguity with an existing rule | A vague, un-scoped rule that passes the structural validator but collides with two existing rules' territory vs. a rule with distinct vocabulary and an explicit "Not for X - see Y" boundary clause, verified against the real validator's parser |
| [02-multi-skill-primary-secondary-routing.md](02-multi-skill-primary-secondary-routing.md) | Contrast | A single request that legitimately spans two domain skills and must be routed to both, with an explicit primary and secondary | Silently invoking only the first-matching rule and treating the request as fully handled vs. checking every rule, stating "primary... with... for..." per `SKILL.md`'s own behavior rule, and invoking the primary first |
| [03-negative-carve-out-not-a-match.md](03-negative-carve-out-not-a-match.md) | Contrast | Recognizing when a request only superficially matches a routed keyword and should not trigger that rule, per the rule's own stated negative carve-out | Pattern-matching the bare substring "root" straight to `hep-analysis` vs. checking the rule's own "Not for unrelated uses of 'root'" clause and correctly proceeding with no skill invoked |
| [04-trajectory-single-clean-match-academic-papers.md](04-trajectory-single-clean-match-academic-papers.md) | Execution Trajectory | Writing the abstract for a paper on a neutrino telescope search | Checks all four rules in full rather than stopping at the physics-adjacent subject matter, confirms `academic-papers` alone applies since the ask is prose not analysis, and verifies the relied-on rule text against the live `SKILL.md` |
| [05-trajectory-generic-verb-vs-domain-specific-rule.md](05-trajectory-generic-verb-vs-domain-specific-rule.md) | Execution Trajectory | A ROOT macro segfaults when a branch is added, with the user asking to "refactor... fix" it | Routes to `hep-analysis` alone despite the generic `agile-development`-trigger verbs present, since the domain skill's ROOT-specific rule is strictly more specific for this exact code path |
| [06-trajectory-clean-no-match-proceed-normally.md](06-trajectory-clean-no-match-proceed-normally.md) | Execution Trajectory | A laptop's Wi-Fi drops during video calls - no domain-skill keyword present at all | Confirms zero rules apply and proceeds per Behavior rule 4, diagnosing a real co-channel Wi-Fi conflict directly with no skill mentioned |
| [07-gated-pipeline-adding-a-new-rule.md](07-gated-pipeline-adding-a-new-rule.md) | Gated Pipeline | Adding a new `devops-infrastructure` routing rule without a keyword collision | Three gates - a candidate-keyword collision grep that finds "pipeline" genuinely overloaded across two existing rules, a carve-out draft, and a red-team pass that catches a second collision ("build") the draft's own prose introduced |
| [08-gated-pipeline-disambiguating-figure-interpretation.md](08-gated-pipeline-disambiguating-figure-interpretation.md) | Gated Pipeline | Resolving a real routing ambiguity between `academic-papers` and `hep-analysis` for figure/plot-interpretation requests | Three gates - documenting real misrouted requests, drafting symmetric carve-outs, and a red-team pass that confirms a combined "read + recompute" request should still trigger the existing primary/secondary rule rather than be treated as a new error case |
| [09-gated-pipeline-expanding-a-carve-out.md](09-gated-pipeline-expanding-a-carve-out.md) | Gated Pipeline | Expanding `hep-analysis`'s "root" carve-out after a real false positive (a dental "root canal" question) | Three gates - locating the exact enumerated-list text, a minimal surgical addition, and a red-team pass that honestly logs the list's inherent incompleteness instead of declaring the gap fully closed |
| [10-decision-tree-multi-skill-ambiguous-routing.md](10-decision-tree-multi-skill-ambiguous-routing.md) | Decision-Tree | A request touching multiple skills at once ("refactor this PyTorch training loop so a paper's reproducibility section can describe it accurately") | Formalizes when a domain skill's own specific rule subsumes `agile-development`'s generic code-change trigger, selects `deep-learning` primary / `academic-papers` secondary for this request, and defines fallback re-triage if the trigger was misclassified |
| [11-decision-tree-figure-interpretation-routing.md](11-decision-tree-figure-interpretation-routing.md) | Decision-Tree | A figure/plot request that could belong to `academic-papers`, `hep-analysis`, or `deep-learning` depending on intent | A 5-row matrix selects `hep-analysis` alone for "is this uncertainty band right," recomputes it correctly, and defines fallback re-triage if the fix turns out to affect a published claim |
| [12-decision-tree-multiple-false-positive-keywords.md](12-decision-tree-multiple-false-positive-keywords.md) | Decision-Tree | A request with four simultaneous surface keyword matches (LaTeX, fix, refactor, update) that is really about a personal resume | A 5-row matrix resolves every surface match to "does not apply" for a resume-editing request, proceeding with no skill invoked, with fallback re-triage if the document turns out to be an academic CV after all |
| [13-elicitation-new-skill-request.md](13-elicitation-new-skill-request.md) | Elicitation | "Add a new skill for technical writing" - no bullet wording, carve-outs, or trigger phrases named | Resolves to a new routing-rule bullet plus a carve-out confirming an existing `agile-development` case still routes correctly, verified against `validate_skill_bundle.py`'s sibling-folder check |
| [14-elicitation-two-skills-request.md](14-elicitation-two-skills-request.md) | Elicitation | "This request should probably use two skills, can you check?" - no named skills, primary/secondary order, or test prompt given | Resolves to a concrete two-skill example (`deep-learning` primary, `agile-development` secondary) documented as a regression-detectable test case, without changing either bullet's wording |
| [15-elicitation-router-edge-case-request.md](15-elicitation-router-edge-case-request.md) | Elicitation | "Can you make the router better at catching edge cases?" - no false-positive example, implicated rule, or fix type named | Resolves to a single confirmed "fit" false-positive against the `hep-analysis` bullet, fixed with a targeted carve-out verified not to break a genuine physics-fit request |
| [16-adversarial-audit-new-routing-rule-proposal.md](16-adversarial-audit-new-routing-rule-proposal.md) | Adversarial Audit | A proposed new `frontend-design` routing-rule bullet for a hypothetical sixth skill | Attacks an unflagged keyword collision with `agile-development`'s "UI work" trigger and a missing "Not for X" exclusion clause, patching in an explicit primary/secondary resolution mirroring the collection's existing conventions |
| [17-adversarial-audit-fallback-text-proposal.md](17-adversarial-audit-fallback-text-proposal.md) | Adversarial Audit | A proposed Behavior-rule-3 rewrite to have the router "briefly explain why" on a non-match, instead of proceeding silently | Two attack vectors - narrated-explanation overhead on true negatives and no actual gain on a genuine near-miss - closed by keeping routing rules' own carve-out text as the precision mechanism instead of adding a narration layer |
| [18-adversarial-audit-bullet-consolidation-proposal.md](18-adversarial-audit-bullet-consolidation-proposal.md) | Adversarial Audit | A proposal to merge the academic-papers and hep-analysis routing bullets into one "physics-writing-and-analysis" bullet | Two attack vectors - a lost argument-vs-value disambiguation and reference sets no longer matching the merged bullet's claimed scope - closed by keeping the bullets separate and each skill's own references attached |
| [19-test-first-routing-parser-primary-secondary.md](19-test-first-routing-parser-primary-secondary.md) | Test-First | A routing-table parser must resolve a request naming two overlapping domains to (primary, secondary) in the documented order | Red on an alphabetical-order resolver that wrongly promotes `agile-development` to primary, green on a resolver that demotes the generic fallback per Behavior rule 2's own worked example |
| [20-test-first-sibling-discovery-invariant.md](20-test-first-sibling-discovery-invariant.md) | Test-First | `find_sibling_skill_dirs` must exclude a sibling directory whose `SKILL.md` exists but is empty | Red on a bare `.exists()` check counting an empty-stub skill as installed; green on a non-empty-content check that correctly excludes it |
| [21-test-first-bundle-validator-message-invariant.md](21-test-first-bundle-validator-message-invariant.md) | Test-First | The bundle validator must reject a `SKILL.md` whose frontmatter exceeds the 1024-character plugin spec limit | Red on a validator with no length check accepting an oversized frontmatter; green on an added check that catches it locally before a plugin loader would |
| [22-postmortem-missing-carve-out-hijack.md](22-postmortem-missing-carve-out-hijack.md) | Postmortem | A new routing-rule bullet merged without a carve-out hijacked unrelated requests for two days before it was noticed | 5 Whys trace to a regression suite that only covers pre-chosen scenarios; fix adds a CI keyword-collision checker blocking any new bare term matching the cross-skill denylist without a carve-out |
| [23-postmortem-frontmatter-length-truncation.md](23-postmortem-frontmatter-length-truncation.md) | Postmortem | An edit to `SKILL.md`'s `description` field pushed it past the platform's character limit, silently truncating a routing bullet | 5 Whys trace to no local check for a limit that only existed as undocumented platform behavior; fix adds a `validate_skill_bundle.py` gate blocking any oversized `description` field |
| [24-postmortem-generic-verb-double-routing.md](24-postmortem-generic-verb-double-routing.md) | Postmortem | Two routing bullets both claimed the generic verb "update" with no specificity ordering, causing recurring ambiguous double-routing | 5 Whys trace to a lesson learned once but never encoded as a checkable rule; fix adds a CI test protecting the specificity-ordering text plus a similarity-based review flag |
