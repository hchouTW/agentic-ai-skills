# agile-development Examples

Canonical worked examples in this skill's own domain, one of four archetypes
each - see [../references/example-authoring.md](../references/example-authoring.md)
for the archetype-selection guide and how these are generated and validated.

| Example | Archetype | Scenario | One-line takeaway |
|---|---|---|---|
| [01-bug-fix-scoping-review.md](01-bug-fix-scoping-review.md) | Contrast | Scoping and reviewing a bug fix for a cart total that is wrong when a discount code is applied | A one-off patch that special-cases the reported codes vs. a failing-test-first fix that states and implements the missing stacking contract with exact decimal arithmetic |
| [02-new-feature-slicing-and-acceptance-criteria.md](02-new-feature-slicing-and-acceptance-criteria.md) | Contrast | Scoping a new "let admins export a CSV of active users" feature request | A broad, unreviewable PR bundling a dashboard, job queue, and email notifier on a silently-guessed "active user" definition vs. given/when/then acceptance criteria, an explicit stated assumption, and the smallest vertical slice with deferred follow-ups |
| [03-production-incident-response-postmortem.md](03-production-incident-response-postmortem.md) | Contrast | Responding to and writing the postmortem for a checkout outage caused by a locking database migration | Root-causing during live impact and a blaming, vague postmortem vs. stabilize-first rollback and a blameless, timestamped postmortem with systemic contributing factors and owned action items |
| [04-trajectory-discount-stacking-bug.md](04-trajectory-discount-stacking-bug.md) | Execution Trajectory | Walking the same discount-stacking bug report (a fourth recurrence) from raw ticket to a verified fix | A reset-instead-of-compound bug that silently discarded one of two stacked discounts, walked start-to-finish: triage, canonical-order fix, deleted superseded one-off patches, and passing regression tests |
| [05-gated-pipeline-payment-provider-rollout-rfc.md](05-gated-pipeline-payment-provider-rollout-rfc.md) | Gated Pipeline | Drafting and shipping an RFC for a feature-flagged progressive rollout of a new checkout payment provider | Three explicit gates - gap formulation, draft aligned to this skill's own design-doc checklist, and a red-team pass that found a false idempotency assumption and added a required fix before the merge gate |
| [06-decision-tree-incident-mitigation-triage.md](06-decision-tree-incident-mitigation-triage.md) | Decision-Tree | Triaging an ambiguous production incident page and choosing the fastest safe mitigation before root-causing | Formalizes this skill's own Incident Response playbook step into a trigger-to-mitigation matrix, selects the deploy-rollback branch for the reported page, and defines fallback triage if the mitigation fails or the trigger was misclassified |
| [07-trajectory-database-migration-lock.md](07-trajectory-database-migration-lock.md) | Execution Trajectory | A NOT NULL column migration holds a production table lock for minutes, causing timeouts | Traces the lock to single-statement NOT NULL validation under ACCESS EXCLUSIVE, walked through a three-step nullable-add / batched-backfill / validated-constraint fix verified against an 11.2M-row staging replay with zero timeouts |
| [08-trajectory-dependency-update-silent-break.md](08-trajectory-dependency-update-silent-break.md) | Execution Trajectory | A "minor" dependency bump silently changes rounding behavior, caught weeks later by finance reconciliation | Traces a $0.01-per-invoice discrepancy to a rounding-mode default change untested because no fixture used an exact rounding boundary; pins the mode explicitly and adds a version-independent regression test |
| [09-gated-pipeline-legacy-billing-strangler-fig.md](09-gated-pipeline-legacy-billing-strangler-fig.md) | Gated Pipeline | Replacing a legacy, untested billing module with a new implementation while it stays load-bearing | Three gates - characterization tests and a seam before any change, a strangler-fig rollout with a deliberately-chosen dependency direction, and a red-team pass that catches a false per-request independence assumption and fixes the routing granularity |
| [10-gated-pipeline-public-api-contract-change.md](10-gated-pipeline-public-api-contract-change.md) | Gated Pipeline | Adding a required field to a shared public API contract without breaking existing external integrations | Three gates - a per-partner capability inventory, an ADR choosing a phased optional-field rollout over an immediate breaking change, and a red-team pass that finds one partner's strict response-schema parsing would break even on an "optional" field |
| [11-decision-tree-pr-review-response-triage.md](11-decision-tree-pr-review-response-triage.md) | Decision-Tree | Reviewing a colleague's pull request and deciding how to respond to each category of finding | Formalizes this skill's own severity-distinction review guidance into a finding-to-response matrix, selects "verify the claim directly" for a PR whose description contradicts its own linked CI run, and defines fallback re-triage for a flaky-vs-real failure |
| [12-decision-tree-staging-vs-production-parity-triage.md](12-decision-tree-staging-vs-production-parity-triage.md) | Decision-Tree | A feature works in staging but misbehaves in production, cause unknown | Formalizes a config/flag/scale/infrastructure/data elimination order into a triage matrix, selects the missing-production-secret branch for a silently-failing scheduled email, and fixes both the missing secret and the silent-failure pattern that hid it |
