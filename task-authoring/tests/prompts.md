# Fresh-model behavior prompts for task-authoring

Each prompt is run in isolated `claude -p` children in two arms: `baseline` (no skill visible) and `skill`
(`task-authoring` symlinked as a project skill, the child told to read its `SKILL.md`). Both arms get a copy of
`tests/fixtures/shop_repo` as the working directory and may Read/Glob/Grep it; nothing can be edited or run. The
`tmpl` fixture is `shop_repo` plus a repository task template (`docs/TASK_TEMPLATE.md`, built by the script).
`tests/behavior_eval.py` scores each lettered bullet P / ~ / F with a blind scorer. Bullets are scored on the
written task, not on actions. Fixture facts the scorer needs: there is no signup flow, no `app/invoices.py`, no
`lodash` import in code (only in `package.json`), no `docs/` except in `tmpl`, no CI config, no benchmark, no row
counts; auth is a Bearer-token `before_request` in `app/auth_middleware.py`; CSV export is `CsvExporter` in
`app/exporters.py`; the `orders` table has `legacy_id`, read by `app/billing.py`.

(d) Acceptance Criteria are verifiable (concrete status codes, content type, or tests), not "works correctly". |

(e) Does not invent a ticket number or a CI system. |
