**1. Primary AMS source to check against**
- The AMS proton flux, 1 GV to 1.8 TV, is PRL 114, 171103 (2015), S06. It was read at full-text level (main article only; the Supplemental Material tables were not read). [Documented, C05, C31]
  - The abstract gives 300 million events and a spectral index that hardens with rigidity (C05).
  - The analysis used the first 30 months, 19 May 2011 to 26 Nov 2013, in 72 rigidity bins from 1 GV to 1.8 TV (C31).
- The Phys. Rept. 894 review (S01) gives a later 1-billion-event proton measurement from 1 GV to 1.8 TV [Documented, C78]. It does not replace the 2015 paper's tabulated values for a bin-by-bin check.
- Time-resolved proton fluxes are separate datasets and answer different questions. Daily proton fluxes are in S43 (2011-2019, 1-100 GV, C36). Bartels-rotation and daily series are not the time-averaged flux.
- Use these papers to supply the AMS values you cross-check against. The paper wins in any disagreement.

**2. CRDB (LPSC Grenoble), https://lpsc.in2p3.fr/crdb/**
- What it is: a Tier 6 secondary compilation of cosmic-ray data from 10^6 to 10^21 eV, entered from publications with ADS and DataThief. [Documented, C125]
  - It offers a website, a REST interface, a pip-installable Python library (`pip install crdb`) and exports in USINE, GALPROP and csv formats. [Documented, C125, C128]
  - On 2026-10-02 the page stated version V4.2 (September 2026), 143 experiments and 614 publications. Counts change per release, so record the version and retrieval date. [Documented, C125]
- What it holds for AMS proton flux: [Unknown/needs input]. One test query on 2026-10-02 (proton flux, native rigidity axis, `exp_dates=AMS`, conversions and combinations off) returned two AMS02 sub-experiments, with ranges 2011/05/19-2013/11/26 and 2011/05/19-2018/05/26 (72 rows each). The CRDB release was not recorded, no value was compared with a paper, and no ledger claim rests on it.
- How to query it:
  - Use `scripts/crdb_query.py` with `--num H --energy-type R`. A native-axis AMS query adds `exp_dates=AMS&combo_level=0&energy_convert_level=0`. Run one polite request and never retry a block. [General method, C128]
  - Keep the rigidity axis with conversions off. The AMS proton paper is in rigidity.
  - Do not merge sub-experiments. The default returns all datasets regardless of period overlap, and time series are excluded by default (`time_series=no`). [Documented, C126, C128]
  - Map each `SUBEXP_NAME` to its paper through its name and data-taking range. The 2013-11-26 end date matches the 30-month period of S06 and C31. The 2018 one is a different dataset and analysis.
  - A systematic of 0 means "not separately quoted" for old data. Take AMS systematics from the paper, not from CRDB. [Documented, C126]
  - Note `PUBLI-DATAORIGIN` (table or plot). A value transcribed from a plot can differ from the tabulated paper values.

**3. ASI SSDC Cosmic Ray Database, https://tools.ssdc.asi.it/CosmicRays/sf_search.jsp**

This is a different service from CRDB. Its page shows "Version 3.3" and calls itself "CRDB", so do not confuse it with the LPSC V4.2. Only one screenshot of its search form was seen, on 2026-10-02, and no query was run. [Documented, C183; 2017 proceedings abstract C130]

What the page states it offers:
- Access to published data from missions dedicated to charged cosmic-ray measurements. The data-set is "not comprehensive but in expansion".
- The data sit in a SQL database. You search by particle species, measurement and/or mission name, and a refined search is available.
- Results come as a table ready to plot, export and download. They include the published points with their uncertainties and some meta-data.
- Manipulated data (for example energy-rigidity conversion or unit change) are flagged in the output file. The page tells users to consult the original publication.
- The form has a Particle selector, a Plot selector pair, an Experiments selector reading "All selected (25)", special-dataset boxes "SEP events" and "trapped", and a button "Most recent time-dependent AMS data available here!". There are Login and "Feedback and contacts" links.
- The 2017 proceedings (C130) describe it as "under development" and built to support PAMELA and AMS-02 retrieval. That is older context, not a description of current holdings.

**4. Cross-check recipe**
1. Fix the estimand: proton flux in rigidity, time-averaged, 1 GV to 1.8 TV, 19 May 2011 to 26 Nov 2013. Note that the unit is (m^2 sr s GV)^-1.
2. Take the AMS values from S06 (tables or figures in the paper, which you hold). Label them as the primary source.
3. Query each database on the native rigidity axis. Record the database name, version, retrieval date and the dataset name and period.
4. Compare bin edges, value, and statistical and systematic uncertainty separately.
5. Pick a metric and a trigger in advance. Example: a per-bin difference above some fraction of the total error means a different dataset, a rebinning or a transcription error to investigate. "Consistent" alone is not validation.
6. Compare your own flux to the AMS values on the same rigidity bins and the same data period. If you convert to kinetic energy, state Z=1, A=1 and the proton mass, and run `scripts/ams_kinematics.py`.
