**What to do instead for your cross-check [General method]**
1. Fix the variable. The AMS proton flux paper (PRL 114, 171103, 2015; 1 GV-1.8 TV; ledger S06/C05) is a flux in rigidity. Query on that native axis and don't convert to energy.
2. Run the CRDB query on the native axis with conversions and combinations off:
   `scripts/crdb_query.py fetch --num H --energy-type R --out FILE`
   This sends the query with `exp_dates=AMS&combo_level=0&energy_convert_level=0`. Then run `summarize FILE`. Record the CRDB version and the retrieval date.
3. Do not merge or average sub-experiments.
   - A single earlier test query (2026-10-02, release not recorded, no values compared) returned two AMS02 sub-experiments, with data-taking ranges 2011/05/19-2013/11/26 and 2011/05/19-2018/05/26 (72 rows each). Content changes with each CRDB release, so re-run the query.
   - Time series are excluded by default.
   - Map each sub-experiment to its AMS paper by name and period. The paper's numbers win wherever they differ.
   - A CRDB systematic of 0 means "not separately quoted". Take systematics from the paper.
4. Compare bins, values and uncertainties against the paper's own table and figures, not against my recollection. Say which database each number came from. They are separate services.
