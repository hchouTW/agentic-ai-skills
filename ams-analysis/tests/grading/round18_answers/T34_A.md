This is a generic RooFit question with no AMS-02 tie, so the ams-analysis skill does not apply. The hep-analysis skill is the right one, and this is a standard method. The numbers below are illustrative placeholders, not tuned values.

**Model.** Use a Crystal Ball (Gaussian core with a power-law tail on one side). The usual choice for a dimuon peak is a tail on the low-mass side from final-state radiation and energy loss. A double-sided Crystal Ball (`RooCrystalBall`, ROOT >= 6.20) is often better when both sides have tails. The classic `RooCBShape` has one tail only.

```cpp
using namespace RooFit;
RooRealVar m("m","m_{#mu#mu} [GeV]",85,97);
RooRealVar mean("mean","mean",91.19,89,93);
RooRealVar sigma("sigma","sigma",1.5,0.3,4);
RooRealVar alpha("alpha","alpha",1.5,0.1,5);   // transition point, in units of sigma
RooRealVar n("n","n",3,0.5,50);                // tail power
RooCBShape cb("cb","CB",m,mean,sigma,alpha,n);
// Z->mumu: usually add a background. For a mass window with a low-mass tail, use an exponential:
RooRealVar tau("tau","tau",-0.05,-1,0);
RooExponential bkg("bkg","bkg",m,tau);
RooRealVar ns("ns","ns",1e4,0,1e7), nb("nb","nb",1e3,0,1e7);
RooAddPdf model("model","model",RooArgList(cb,bkg),RooArgList(ns,nb));

RooFitResult* r = model.fitTo(data, Extended(true), Save(true), PrintLevel(-1)); // use SumW2Error(true) or AsymptoticError(true) for weighted data
r->Print("v");
alpha.Print(); n.Print();
```

For an unbinned fit, `data` is a `RooDataSet` with `m` as the observable. For a binned fit, use a `RooDataHist`. Parameters from the fit are read via `alpha.getVal()` and `alpha.getError()`, or `r->floatParsFinal()`.

**Extracting the tail parameters.**
- `alpha` is where the Gaussian core joins the power-law tail, in units of sigma. The sign convention matters: in `RooCBShape` the tail is on the low side when alpha > 0. Check this against the plot.
- `n` is the power-law exponent.
- `alpha` and `n` are strongly anti-correlated, so check `r->correlationMatrix()`. A fit with `n` at its upper limit means the tail is not constrained by the data.
- Because `n` is poorly determined, a common practice is to fix `n` (for example, from simulation or a high-statistics control sample) and float only `alpha`. Or take both from simulation and fit data with a Gaussian-smeared version of that shape. Document whichever you choose and vary it as a systematic.

**Practical advice.**
1. Fit simulation first, where the truth is clean, to set starting values and tail parameters. Then fit data with the tail fixed or constrained (`RooGaussian` constraint with `ExternalConstraints`).
2. Choose the mass window so the tail is populated, but not so wide that the background shape dominates. The background and tail are partially degenerate. Test the sensitivity by varying the background shape (exponential, polynomial) and the fit range.
3. If the line shape is a Breit-Wigner convolved with detector resolution, as for the Z, the Crystal Ball models the resolution alone. Use `RooVoigtian`, or a Breit-Wigner convolved with a Crystal Ball (`RooFFTConvPdf`), when the natural width matters. For J/psi or Upsilon the natural width is small, so the CB can model the whole peak.
4. Check the fit quality with the pull distribution, the chi2/ndf of a binned fit, and `r->status()` and `covQual()` (expect 0 and 3). Use `RooMinimizer` with MINOS (`Minos(true)`) for asymmetric errors on `alpha` and `n`, because they are non-Gaussian when poorly constrained.
5. Plot with `m.frame()`, `data.plotOn`, `model.plotOn`, and the components with `Components("cb")`, to see the tail in log scale.
6. Never extend a Gaussian-core resolution estimate into the tail without checking it. The tail parameters are where the fit is least robust.
