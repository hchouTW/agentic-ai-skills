## CRDB (LPSC Grenoble), https://lpsc.in2p3.fr/crdb/

- **What it is** [Documented, S50, C125-C128]: cosmic-ray data and meta-data from 10^6 to 10^21 eV, entered from publications. It has a website, a REST interface and a pip-installable Python library (`pip install crdb`). Exports are in USINE, GALPROP and csv formats. It also lists the AMS02 datasets by sub-experiment.
- **Values**: [Unknown/needs input]. I have no web access, so I cannot query it. The values depend on the release, and the content changes with each one (C125, C129). Any number I gave you would be a guess.
- **One earlier test query** (2026-10-02, proton flux, native rigidity axis, `exp_dates=AMS`, conversions and combinations off): it returned two AMS02 sub-experiments with different data-taking ranges, 2011/05/19-2013/11/26 and 2011/05/19-2018/05/26 (72 rows each). The CRDB release was not recorded. No value was compared with a paper, and no ledger claim rests on it. Treat it as an illustration only and run a fresh query.
- **How to get the values yourself** [General method]: run `scripts/crdb_query.py`. It builds the REST URL, makes one polite request, never retries a 401/403/429, and writes a sidecar file recording the request and retrieval time. A native-axis AMS query adds `exp_dates=AMS&combo_level=0&energy_convert_level=0` (C128).
  - Record the CRDB version and the export date with anything you extract.
  - Query with the same variable as the AMS paper (rigidity, with `energy_type=R`) and keep conversions off. Approximate conversions can add systematic errors larger than the data uncertainties (C127).
  - Do not merge sub-experiments or average datasets (C126). Time series are excluded by default (`time_series=no`, C128).
  - A systematic of 0 in CRDB means "not separately quoted" (C126). Take AMS systematics from the paper.
- **Which paper to check against**: map each returned `SUBEXP_NAME` to its AMS paper by name and data-taking range. The AMS proton flux paper in the index is S06, PRL 114, 171103 (2015), 1 GV-1.8 TV. It is full-text verified for the main article only, and its Supplemental Material was not opened. The daily proton periodicity paper is S43 (2021). Match the period and range to the claim's scope before comparing. I am not quoting flux numbers here, since I am not citing a claim ID for a specific value. Compare value, bins and uncertainty with the paper. Note the `PUBLI-DATAORIGIN` column (table or plot), because a transcription from a plot can differ from the paper's table.

## How to do the cross-check

1. Fix the estimand and variable: proton flux versus rigidity, and which dataset (time-averaged, per Bartels rotation, or daily).
2. Pull the AMS proton datasets from CRDB on the native rigidity axis with the script above, and record the version and date.
3. Open the same species and range in the SSDC page by hand, and record what you see and when.
4. Compare each database with the primary AMS paper (S06, or S43 for daily fluxes), not with each other. Agreement between two secondary compilations is not validation. State a metric, for example the maximum relative difference per bin against the paper's table, and a trigger, for example any bin differing by more than its quoted total uncertainty. On a mismatch the paper wins. Report a transcription or rebinning difference to the database maintainers.
5. Your own AMS proton flux is a user-supplied number, so I will label it that way. If you send it together with the bin edges, the variable and the period, I can help set up the comparison.
