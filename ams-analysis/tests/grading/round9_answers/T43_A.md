**Short answer:** your colleague is half right. The number 3.0 is correct only in one specific case, and "whatever the background is" is wrong. Treat the 30% background uncertainty as a nuisance parameter, not as a footnote.

## Where 3.0 comes from [General method]

For N = 0 observed events, the exact Poisson 95% bound on the **total** mean (signal plus background) is -ln(0.05) = 2.996, about 3.0. That figure does not depend on the background. It is the limit on s + b.

The limit on the **signal** is what you want. For a known background b, the classical limit is

s_UL = -ln(1 - CL) - b

This shrinks as b grows. For your b = 0.5, s_UL = 2.996 - 0.5 = 2.50 (script output, `poisson_diagnostics.py upper-limit --n 0 --b 0.5 --cl 0.95`). It is only 3.0 for b = 0. The classical zero-count limit is therefore not "independent of the background".

The classical value also has a problem. Once b reaches 3.0, it becomes zero or negative. That is a known pathology: it excludes signals you have no sensitivity to. The result is a downward fluctuation that looks stronger than your experiment can deliver.

A flat-prior Bayesian limit is independent of b for N = 0, which may be the source of the "whatever the background is" claim. That answers a different question: a posterior with a prior on s, not a frequentist coverage statement. A flat prior on s is also a choice you would have to state.

## Which number to quote [General method]

All values are for N = 0, b = 0.5, 95% CL, with the background treated as exactly known unless noted.

| Construction | Upper limit on s |
|---|---|
| Classical | 2.50 |
| Feldman-Cousins (unified, s >= 0) | 2.63 |
| CLs | 3.00 |
| CLs with sigma_b = 0.15 (see below) | 3.00 |

- **CLs** gives 2.996 here because with N = 0 it equals the zero-background value. CLs is conservative by design and is not a frequentist interval. This is probably the construction in which your colleague's "3.0 regardless of background" is exactly true for N = 0, so ask which one they mean.
- **Feldman-Cousins** is a frequentist interval that is never empty or negative. The lower bound of 0 is expected behavior at N = 0, not a failure.
- Pick the construction **before** looking at the data and say which one it is. Report the **expected sensitivity** next to the observed limit. CLs gives the median expected limit under background only, and for CLs here it is 3.0 with a +1 sigma band at about 4.4.

## What to do about the uncertain background

I read "30% uncertainty" as sigma_b = 0.15 events, with b = 0.5. These are **user-supplied** numbers, taken as given.

1. **Do not ignore it, and do not use the known-background formula as if b were exact.** An exact Poisson interval assumes an exactly known b.
2. **Understand where the 0.5 comes from.** Its origin decides the right nuisance prior. A control-region count or MC statistics argues for a Poisson/gamma prior. A systematic scale factor argues for a log-normal. A symmetric Gaussian on a 0.5 mean with 30% width is fine here, but check the choice against the origin.
3. **Treat b as a nuisance parameter.** Use a profile-likelihood or toy construction, or Cousins-Highland marginalization, and **vary sigma_b** to see how much the answer moves.
4. **Do not use S/sqrt(B), Wilks, or Gaussian errors at N = 0.** The count is on a boundary and the numbers are small.

Script results with sigma_b = 0.15 [General method]:

- CLs with a marginalized background: observed 2.996, unchanged from the known-background case at this precision. The +1 sigma expected value moves from 4.36 to 4.37 and +2 sigma from 5.82 to 5.83. At N = 0 the background uncertainty hardly matters for the CLs limit.
- Toy-calibrated profile-likelihood limit: about 2.67 (seed 1, 4000 toys). Treat this as a toy-noise-limited step-wise estimate. The asymptotic value, 1.35, is not trustworthy at these counts.
- Berger-Boos guaranteed-coverage limit (beta = 0.01): about 3.23, versus 2.66 for the plug-in profile. The Berger-Boos value is the price of guaranteed coverage over all true backgrounds, not evidence that the plug-in fails.

So with this background, the limit lies between about 2.5 and 3.2 depending on construction, and 3.0 (CLs) is a reasonable and defensible quote. The spread between constructions is itself a method systematic: report it.

## Practical recommendation [Proposal]

- Quote the **CLs limit with its expected band**, about 3.0 on the signal count.
- Show the profile and Berger-Boos values as cross-checks and state the construction used.
- Show the dependence on sigma_b (for example 0.15 and a larger value).
- If you need a flux or ratio limit, convert with the exposure: Phi_UL = N_UL / (exposure x bin width), and propagate the exposure uncertainty as another nuisance. The count limit of 3.0 does not carry over unchanged if the efficiency and acceptance are uncertain.
- If this is a rare-event search (for example antinuclei), the background estimate and its tails (charge confusion, misidentification) need validation from the tail of the response, not the Gaussian core. I have not used any AMS-specific numbers here, and the 0.5 and 30% are yours.

## Summary

You and your colleague agree at b = 0, where the limit is about 3.0. With b = 0.5 and N = 0, the classical signal limit is 2.50, Feldman-Cousins 2.63, and CLs about 3.0. The 30% uncertainty changes the result by well under 10%, but the answer to "who is right" is: 3.0 is a correct number for the **total** count and for CLs at N = 0, but not "whatever the background is" for the classical signal limit.
