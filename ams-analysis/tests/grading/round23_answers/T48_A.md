## 2. The two databases: what is documented, what is unknown

Both are Tier 6 secondary compilations. Neither is a source of an AMS result, and a database value is only a transcription of the paper.

### CRDB (LPSC Grenoble), https://lpsc.in2p3.fr/crdb/ [Documented, S50, C125-C128]

- It holds cosmic-ray data and meta-data from 10^6 to 10^21 eV, entered from publications.
- Access is by website, REST interface and the pip-installable `crdb` Python library. Exports are USINE, GALPROP and csv.
- On 2026-10-02 the page stated V4.2 (September 2026) with 143 experiments and 614 publications. These counts change with each release.
- One test query was run on 2026-10-02 (proton flux, native rigidity axis, `exp_dates=AMS`). It returned two AMS02 sub-experiments, 2011/05/19-2013/11/26 and 2011/05/19-2018/05/26, 72 rows each. The CRDB release was not recorded. **No value was compared with the paper, and no ledger claim rests on it.** So I can report the structure of the result but not its values or their agreement with S06.
- Caveats [Documented, C126-C128]:
  - Sub-experiments must not be merged or averaged. Time series are excluded by default.
  - A systematic of 0 means "not separately quoted", not "zero". Take AMS systematics from the paper.
  - Keep the native rigidity axis. Use combo level 0 and conversion level 0, so no combos or conversions are applied to the data.

### ASI SSDC Cosmic Ray Database, https://tools.ssdc.asi.it/CosmicRays/sf_search.jsp [Documented, S52 at screenshot level, C183; S53, C130]

What the search page offers (seen only as one screenshot of the search form on 2026-10-02, with no query run):

- It is headed "COSMIC RAY Database" ("Database for charged Cosmic Ray measurements"), and it gives access to published data from missions dedicated to charged cosmic-ray measurements.
- The data set is described as "not comprehensive but in expansion".
- The data sit in a SQL database. You search by particle species, measurement and/or mission name, with a refined search available.
- Results come as a table that can be plotted, exported and downloaded. They include the published points with uncertainties and some meta-data.
- Manipulated data (for example an energy-rigidity conversion or a unit change) are flagged in the output file. Consult the original publication.
- The form has a Particle selector, a pair of Plot selectors, and an Experiments selector reading "All selected (25)". There are special-dataset boxes ("SEP events", "trapped"). There is a button "Most recent time-dependent AMS data available here!". There are also Login and "Feedback and contacts" links.
- The 2017 proceedings (S53, C130) describe it as built to support PAMELA and AMS-02 retrieval. That is older context, not a description of current holdings.
- **Warning:** the page calls itself "CRDB" and shows "Version 3.3". This is **not** the LPSC CRDB, whose version is V4.2. Always say which database you mean.

## 3. How to get the values and cross-check

1. **Fix the estimand.** Your proton flux needs a rigidity or energy axis, a data period (30-month, Bartels-rotation or daily) and a bin definition. S06 is on the rigidity axis.
2. **CRDB.** Run one query on the native axis. Example REST: `...rest.php?num=H&energy_type=R&exp_dates=AMS&combo_level=0&energy_convert_level=0` (`num`, `den` and `energy_type` are mandatory, C128). The `scripts/crdb_query.py` tool in the skill builds and runs this with a metadata sidecar. Record the CRDB version and retrieval date yourself. Then map each `SUBEXP_NAME` to its AMS paper through name and data-taking range.
3. **SSDC.** In a browser, select Particle = proton, then the AMS experiment. Note the version shown on the page, the retrieval date, the dataset period and whether the output is in rigidity or in energy. If the output is flagged as converted, convert back or re-query so you compare like with like.
4. **Compare each point with the paper's tables** (S06 and its supplement). Compare value, bin edges and uncertainty. Where they differ, the paper wins. The difference may be a plot transcription, a rebinning or a different data period. Report real discrepancies to the database maintainers.
5. **Cross-check your own flux against the paper values, not against the databases alone.** Agreement is only consistency. State a metric, for example per-bin ratio with its total uncertainty, and a trigger for action (for example a deviation beyond the combined uncertainty in more than a stated number of adjacent bins). Do not rely on "reasonable agreement".
