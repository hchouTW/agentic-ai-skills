**Ground rules for the cross-check**
- CRDB and the SSDC database are both secondary compilations of published data (Tier 6). They are for navigation and cross-checking only.
- A value from either is a transcription, never an AMS result. Label it e.g. `[Secondary: CRDB, version V, retrieved date]`.
- The primary source for the AMS numbers is the AMS paper's own tables and figures. [Documented, S06/C05, C31] gives the 2015 PRL 114, 171103 proton flux: 1 GV-1.8 TV, 300 million events, 72 rigidity bins, first 30 months (19 May 2011 to 26 Nov 2013). The index records no flux table values from it. The Phys. Rept. review (S01) reports a later 1 GV-1.8 TV result with 1 billion proton events, with fit parameters but not per-bin fluxes [Documented, C78, abstract/secondary-level]. Time-resolved proton fluxes also exist (daily, 1-100 GV, S43/C36).
- Compare on the native axis. The AMS proton flux is in rigidity, so query with the rigidity axis and conversions off. Do not merge sub-experiments or time series.

**CRDB (LPSC Grenoble, https://lpsc.in2p3.fr/crdb/)** [Documented, S50, C125-C128]
- It holds leptons, nuclei, antinuclei and anisotropy data from 10^6 to 10^21 eV, entered from publications.
- Access is by website, REST and a pip-installable `crdb` Python library. Exports are USINE, GALPROP and csv.
- On 2026-10-02 the page stated V4.2 (September 2026), with 143 experiments from 614 publications. Counts change with each release.
- One test query was run on 2026-10-02: proton flux, rigidity axis, `exp_dates=AMS`, combo level 0, conversion level 0. It returned two AMS02 sub-experiments with different data-taking ranges: 2011/05/19-2013/11/26 and 2011/05/19-2018/05/26 (72 rows each). The CRDB release was not recorded and no values were compared with a paper. Do not rely on this; re-run it.
- To query: `scripts/crdb_query.py fetch --num H --energy-type R --out FILE`. It records a metadata sidecar and never retries on a 401/403/429 block. A REST pattern is `...rest.php?num=H&den=&energy_type=R&exp_dates=AMS&combo_level=0&energy_convert_level=0`; check the parameters on the page (C128).
- Then map each `SUBEXP_NAME` to its AMS paper by name and data range. The 2011/05/19-2013/11/26 range matches S06 (C31); the other range does not match S06 and must be identified, not assumed.
- A systematic of 0 in CRDB means "not separately quoted" (C126). Take AMS systematics from the paper, not from CRDB.
- Check the `PUBLI-DATAORIGIN` column (table or plot). Where CRDB and the paper differ, the paper wins.
- Record the CRDB version and retrieval date.

**ASI SSDC Cosmic Ray Database (https://tools.ssdc.asi.it/CosmicRays/sf_search.jsp)** [Documented, S52 search page at screenshot level, C183; S53 2017 abstract, C130]
- Only the search form was seen, as one screenshot dated 2026-10-02. No query was run, so I do not know what AMS data it holds.
- What the page says:
  - It is headed "COSMIC RAY Database" ("Database for charged Cosmic Ray measurements").
  - It offers published data from missions dedicated to charged cosmic-ray measurements.
  - It calls its data-set "not comprehensive but in expansion".
  - Data sit in a SQL database searched by particle species, measurement and/or mission name, with a refined search.
  - Results come as a table to plot, export and download, with published points, uncertainties and some meta-data.
  - Manipulated data (e.g. energy-rigidity conversion, unit change) are flagged in the output file, and users should consult the original publication.
- Form controls: a Particle selector, a Plot selector pair, an Experiments selector reading "All selected (25)", special-dataset boxes "SEP events" and "trapped", and a button "Most recent time-dependent AMS data available here!".
- It labels itself "CRDB" and shows "Version 3.3". That is not the LPSC CRDB (V4.2). Always say which database you mean.
- Unknown: which 25 experiments, which AMS-02 datasets and periods, the output formats, access terms, and whether login is needed. I will not describe these. Do not script requests to it (scripted requests got HTTP 429, timeouts and a single-sign-on redirect). Use a browser: select Particle = proton, pick AMS, and note the version, date and flagged conversions.
- A 2017 proceedings (S53, C130) describes it as "under development" for PAMELA and AMS-02 retrieval. That is older context, not its current holdings.

**Suggested workflow**
1. Take your own flux and the AMS paper's table (S06 for the 2011-2013 result) as the reference.
2. Pull the CRDB AMS proton datasets on the native rigidity axis. Pull the SSDC proton/AMS table by browser, and check for conversion flags.
3. Match period, bins and variable between each database row and the paper before comparing.
4. State a metric and a trigger, e.g. a per-bin ratio to the paper with a threshold that prompts investigation. "Reasonable agreement" is not validation.
