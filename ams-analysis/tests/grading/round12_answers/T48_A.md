**What I can say about the two databases**

Both are secondary compilations of published data. Use them for navigation and cross-checking, never as the source of an AMS number. Every AMS value should be traced back to the AMS paper.

- **CRDB (LPSC Grenoble), https://lpsc.in2p3.fr/crdb/** [Documented, S50, C125-C128; secondary]:
  - It is a database of cosmic-ray data and meta-data from 10^6 to 10^21 eV, entered from publications.

  - On 2026-10-02 the page stated version V4.2 (September 2026), with 143 experiments from 614 publications (C125). These counts change with each release.

**How to run the cross-check**

1. **Fix the variable.** The AMS proton flux is a rigidity flux, binned in rigidity in the paper. Compare on that axis. Do not convert to kinetic energy per nucleon unless you state Z and A (proton: Z = 1, A = 1, PDG mass) and the conversion is exact.
2. **Query CRDB on the native axis**, restricted to AMS, with conversions and combos off. The page's REST parameters are in C128. A query would add `exp_dates=AMS&combo_level=0&energy_convert_level=0`, with the proton as numerator and the rigidity energy type. The example in my notes was not executed here. The REST endpoint and the `crdb` Python library are documented, but the exact query syntax should be confirmed against the live page.
3. **Match datasets to papers.**
   - Map each returned AMS sub-experiment name to its paper by name and data-taking range.
   - The 2015 time-averaged proton flux (S06, 2011-05-19 to 2013-11-26) is a different dataset from the daily and Bartels-rotation proton fluxes (S41, S43) and from the later solar-cycle papers. The default query returns all datasets regardless of overlap.
   - Time series are excluded by default (C126, C128).
   - Do not average datasets or treat their union as one measurement.
4. **Use the paper as the reference.** Take values, bins, and statistical and systematic uncertainties from the AMS paper (its tables and Supplemental Material), not from the database.
   - A systematic of 0 in CRDB means "not separately quoted" (C126). It is not an AMS statement.
   - If the database and the paper disagree, the paper wins. Possible causes are transcription from a plot, rebinning, or a different data period. Report it to the CRDB team.
5. **Record provenance.** Note the CRDB version and retrieval date, the `PUBLI-DATAORIGIN` field (table or plot), and the energy-scale column.
6. **Define agreement.** Use a stated metric and a trigger for what you do on disagreement. "Consistent with the paper" is not validation.
