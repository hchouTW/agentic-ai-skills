**What you can rely on**

- **The AMS proton flux paper** is PRL 114, 171103 (2015), "Precision Measurement of the Proton Flux, 1 GV-1.8 TV" (S06). The ledger records its main article as read in full text. Its supplemental material was not opened.
  - It reports about 300 million events and a spectral index that hardens with rigidity [Documented, C05, abstract level].
  - It uses the first 30 months, 19 May 2011 to 26 Nov 2013, in 72 rigidity bins from 1 GV to 1.8 TV. Selection includes live time above 50%, a zenith angle of the z axis within 40 degrees, outside the South Atlantic Anomaly, and R above 1.2 times the maximum cutoff. Bin-to-bin migration is corrected by iterative unfolding [Documented, C31].
  - The flux is a function of rigidity, so query that axis. The per-bin flux values and uncertainties are in the paper's tables and supplement, and the ledger has no claim for them.
- **Later AMS proton results** exist, for example the daily proton fluxes and their periodicities (S43, S41). Make sure each database dataset is matched to the right paper and period.
- **Currency:** the skill's index was last verified 2026-09-20. I can't check for newer proton papers without browsing.

**CRDB (LPSC Grenoble), https://lpsc.in2p3.fr/crdb/** [Documented, S50, C125-C128; secondary compilation]
- It holds cosmic-ray data from 10^6 to 10^21 eV: leptons, nuclei, antinuclei and dipole anisotropy. Data are entered from publications, using ADS and DataThief.
- It offers a website, a REST interface and a pip-installable Python library (`pip install crdb`). Exports come in USINE, GALPROP and csv formats.
- On 2026-10-02 the page stated version V4.2 (September 2026). The counts change with each release.
- A native-axis AMS proton query would be `num=H` (check the actual parameter value on the page), `den=` and `energy_type=R`, plus `exp_dates=AMS&combo_level=0&energy_convert_level=0`. The REST example from the page is `curl -L 'http://lpsc.in2p3.fr/crdb/rest.php?num=B&den=C&energy_type=EKN'`. I did not run any query, so the proton parameter values are untested.

**How to do the cross-check**
1. Use the same axis as the paper (rigidity). Turn off combos and energy conversion in CRDB.
2. Match each returned CRDB sub-experiment name and period to the AMS paper (S06 for the 30-month data). Do not average or merge AMS datasets (time-averaged, per Bartels rotation, daily). Time series are excluded by default in CRDB.
3. Note the data origin (table or plot). A systematic of 0 in CRDB means "not separately quoted", so take the systematics from the paper.
4. Record the database version and the retrieval date, and label the values [Secondary: CRDB, V, date].
5. The database is a transcription, so the paper wins if they differ.
