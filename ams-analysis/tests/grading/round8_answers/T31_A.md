**Verdict: the estimator has three defects, two of them double counting and one an unstated assumption. As written, the flux is biased (efficiency applied twice) and the TRD drift is corrected twice. Fix these before any systematic or closure test.** [General method] throughout, since this is a design review with user-supplied inputs. No AMS numbers are quoted.

## 1. Response-matrix efficiency plus an explicit efficiency in the estimator (double counting)

- If the response matrix `R_ij` "already includes efficiency", its column sums are the efficiency (at most 1), i.e. the `includes_efficiency` convention. Efficiency and acceptance are then already inside `R`.
- The count model is `μ_i = Σ_j R_ij · A_j · T_j · Φ_j · Δx_j + Σ_k b_ik`. Inefficiency must live in exactly one place: either in `R` (columns sum to ε) or in `A_j` or an explicit ε (columns of `R` sum to 1, i.e. conditional on the selected sample). Never both.
- So you must either remove the inefficiency from `R` (renormalize it to be conditional on selection and keep ε explicit), or drop ε from the denominator and keep it only in `R`.
- Run `scripts/validate_response.py` with the declared metadata. A column sum below 1 can mean inefficiency, or migration into reconstructed bins outside the tabulated range (under/overflow not stored). Check which reading applies before diagnosing.

## 2. Trigger efficiency on top of that

- Trigger efficiency is a conditional efficiency. If the response/efficiency already in `R` was built from MC with the trigger or from a measurement that includes the trigger condition, multiplying again by a trigger efficiency double counts it.
- If it is separate, it must be conditional: `ε_total = ε_trig · ε_sel|trig · ...`, each factor with a named denominator (the population after the preceding selections).
- Do not multiply marginal efficiencies as if independent. Show independence, or measure the joint efficiency directly. Fréchet bounds apply: two 99% selections give a joint efficiency between 98% and 99%, so 98% is a floor, not an estimate.
- Check combined-efficiency closure in MC: the product of the measured factors versus the truth-level combined efficiency, per bin and per time slice.
- Measure it on an unbiased or prescaled sample, with the prescale handled. Trigger internals are not public, so use only user-supplied definitions [Unknown/needs input].

## 3. TRD gain drift corrected twice (veto and efficiency)

- A single physical effect must be treated in exactly one of four categories: data-quality veto, calibration correction, efficiency correction, or response uncertainty.
- A run veto removes exposure (livetime), so the vetoed periods are excluded from `T`. If you then also fold the same drift into a (time-averaged) TRD efficiency, you correct the same effect twice.
- Options:
  - (a) Apply a time-dependent TRD gain calibration before selection, so the discriminant is stable. Carry only the residual as a template-shape or scale systematic.
  - (b) Veto the bad periods, reduce livetime/exposure accordingly, and measure the TRD efficiency only on the retained periods. Keep a stability systematic only for what remains.
  - (c) Keep the periods and model the drift as an efficiency function of time, with no veto.
- Record the chosen category in the systematic ledger and answer its double-counting check ("is a time-dependent drift counted as both a veto and a systematic?").
- If you veto, also check that the vetoed periods are not still contributing to exposure, and that efficiency is not time-averaged over periods you excluded.

## 4. The flux formula itself

`(N - b) / (livetime × exposure × bin width)`:

- **Livetime and exposure overlap.** Exposure `Σ_t A_eff(t) T_live(t) × geomagnetic transmission` already contains acceptance and livetime. Dividing by livetime and exposure counts the time twice and gets the units wrong (m² sr s squared). Use `Φ = (N - b) / (E · Δx)` with `E` the exposure, or `A · T`, not both.
- **Efficiency and acceptance are distinct.** Decide whether `A_eff` (A_geo times average efficiency) or `A_geo` with a separate ε is used. This is the same one-place rule as in item 1.
- **Raw N minus b is a diagonal-response estimator.** It is valid only if migration between reconstructed and true bins is negligible. For a steep spectrum, upward migration of abundant low-rigidity events dominates even when the resolution core looks small. If you have a response matrix, you are implicitly unfolding or forward folding, so do not also use bin-by-bin division. Either unfold (with the full covariance, validation, and prior variation) or forward-fold `μ_i`. Test the diagonal assumption with the response matrix.
- **Background subtraction.** `b` needs a ledger entry (origin, estimator, control-region contamination, transfer model, closure) and its uncertainty carried, not a fixed number. At low counts use Poisson or exact intervals, not Gaussian.
- **Bin centering.** The flux is a bin average; state the prescription for the quoted position.
- Time-resolved efficiency and acceptance changes must be integrated over time so the product is correct when they vary simultaneously.

## Corrected structure [Proposal]

1. Choose one location for efficiency (inside `R`, or explicit with conditional `R`). Make the trigger a named conditional factor, or confirm it is already in `R`.
2. Use a single exposure `E` (acceptance times livetime times geomagnetic transmission) with no extra livetime factor.
3. Assign the TRD drift to one category and record it in the ledger.
4. Replace bin-by-bin division with unfolding or forward folding if migration is not shown to be negligible. Validate with closure, reweighted-spectrum, and stress tests, and carry the covariance.

The `audit_analysis_spec.py` fields (`corrections` with one `effect_id` per effect, `response.includes`, `estimator.applies`) give a checklist for confirming that each effect is applied once.

## Inputs that would change the verdict

- Whether `R` is conditional on selection or includes efficiency.
- Whether the trigger efficiency is already part of that matrix or MC.
- Whether the "exposure" is already acceptance times livetime.
- Whether the veto period and the efficiency measurement overlap.
- Migration size (is the diagonal estimator adequate?).
