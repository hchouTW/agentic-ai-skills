## Defects, in priority order

**1. Efficiency applied twice: response matrix plus an extra trigger efficiency.**
- If the response matrix "already includes efficiency", then it is the `includes_efficiency` type. Its column sums are the efficiency, at most 1, and the inefficiency lives inside `R`. In that case `A` and `ε` must not be applied again anywhere else.
- Dividing by an additional trigger efficiency, or multiplying by one, applies the same inefficiency a second time.
- Fix by choosing one convention and stating it:
  - (a) `R` is conditional on the selected sample (columns sum to 1). The inefficiency then lives in `A_j` and `ε_j`, which are applied once, as one chain.
  - (b) `R` includes efficiency. Then no `ε`, and no acceptance-efficiency factor, appears elsewhere.
- Check what the trigger efficiency actually is. If "includes efficiency" means selection and reconstruction efficiency only, the trigger efficiency may be a legitimate separate factor. Then it must be excluded from `R`, measured on its own denominator, and listed once.
- Run `scripts/validate_response.py` on the matrix. A column sum below 1 can also be migration outside the tabulated range (under/overflow), so do not read it as inefficiency alone.

**2. The TRD gain drift is corrected twice: run veto plus efficiency.**
- The rule is that one physical effect is treated in exactly one category: veto, calibration, efficiency or response. For a TRD drift:
  - If you veto the runs or periods, you remove exposure. Livetime is reduced for those periods, and you must not also fold the drift into the efficiency for the same period.
  - If the efficiency is measured in the surviving periods and tracks the drift, then the veto has already removed the bad part. Counting both over-corrects.
  - If a calibration (gain correction) absorbs the drift, only the residual becomes a systematic, and neither the veto nor the efficiency should cover it again.
- Pick one treatment per period:
  - Veto the periods where the TRD discriminant is not stable, and shrink `T_live` by exactly that vetoed time.
  - Or calibrate the gain, and carry the residual as a template-shape or efficiency systematic.
  - Or keep a time-dependent efficiency without a veto.
- Check that the veto is in the livetime used in the denominator. A veto applied to `N` but not to the exposure, or the reverse, biases the flux.
- A time-dependent drift counted as both a veto and a systematic is one of the standard double-counting checks. Record the category in the systematic ledger.

**3. The flux formula is the diagonal estimator, which ignores response migration.**
- `(N - b) / (livetime × exposure × bin width)` is `Φ_i = N_i / (Δx_i T_i A_i ε_i)`. It is valid only if bin-to-bin migration is negligible.
- A steep spectrum with finite resolution has appreciable migration even when the resolution core looks small. Abundant low-`R` events migrate upward.
- If you have a response matrix, you should be unfolding or forward folding with it, not dividing by `exposure × width` bin by bin. Using the matrix for part of the correction and the diagonal formula for the rest is inconsistent.
- Test the diagonal estimator against the response matrix before adopting it. If you unfold, validate with closure tests, prior variation and full covariance.

**4. "livetime × exposure" probably double counts time.**
- Exposure is the time-integrated acceptance: `Σ_t A_eff(t) T_live(t) × geomagnetic transmission`. It already contains livetime and acceptance.
- Multiplying by livetime again counts time twice. The denominator should be `E_j × Δx_j` with `E_j = A_j T_j`, where `E_j` is a single number per bin, not a separate livetime times an exposure.
- Also check that `A` appears once. `A_eff` already includes the average selection efficiency, so a separate `ε` is applied on top only if `A_geo` is what you use.
- Also check that the geomagnetic transmission is in the exposure for each rigidity bin, once.

**5. The background subtraction `N - b` needs its own treatment.**
- State where `b` comes from (template fit, sideband, migration matrix) and whether it was estimated before or after the efficiency correction. It must be subtracted in the same space as the counts.
- Include its uncertainty and its correlation with the signal template, plus control-region signal contamination.
- In a likelihood the background enters as `Σ_k b_ik`. A subtraction with a Gaussian error is wrong at low counts.

**6. Other points to check.**
- Bin width: use the true-bin width, and say how the differential flux is assigned to a bin position (not the arithmetic center by default).
- Do not multiply conditional efficiencies as if they were independent (trigger, selection, TRD cut). Measure them conditionally, and check factorization and ordering closure. The TRD cut shares rigidity dependence with other cuts.
- Efficiencies are functions of rigidity, time and geometry, not single numbers.

## Concrete proposal [Proposal]

Write one chain with a single owner per effect:

| Effect | Where it lives |
|---|---|
| Geometric acceptance, `A_geo` | `A_j` |
| Selection and reconstruction efficiency | `ε_j`, or inside `R`, never both |
| Trigger efficiency | its own named factor, only if excluded from `R` |
| Livetime and geomagnetic transmission | exposure `E_j`, once |
| TRD gain drift | one of: veto (reduces `T_live`), calibration (plus residual systematic), or time-dependent efficiency |
| Migration | `R_ij`, with orientation and normalization stated |
| Background | `b_ik` with its own ledger |

If you do not need the response matrix because migration is negligible, then drop the matrix and use the diagonal estimator, with every factor stated once. If you need the matrix, forward fold or unfold and remove the extra efficiency factors.

The `scripts/audit_analysis_spec.py` fields are a good checklist for this: `corrections` with one `effect_id` per effect, `response.includes`, `estimator.applies`, and exposure already containing acceptance and livetime.

## Inputs that would change the verdict

- What exactly the response matrix includes (trigger, selection, reconstruction, geometry), and its column sums.
- Whether the trigger efficiency was measured on a sample that the matrix already accounts for.
- How the TRD veto was defined, and which periods it removed from `N` and from livetime.
- How "exposure" was built, and whether it already contains livetime and acceptance.
- Whether migration is small enough for the diagonal estimator.
