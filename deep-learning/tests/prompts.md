# Fresh-model behavior prompts for deep-learning

Each H-prompt is run in a fresh `claude -p` child twice (`tests/behavior_eval.py`): once as a baseline (no skill) and
once with `deep-learning` available. A blind scorer marks every lettered bullet P (pass), ~ (partial) or F (fail).
Runs are plan-only (Read/Glob/Grep, no repository), so code and logs are pasted into the prompt and bullets about
verification are scored on what the answer claims, not on what it ran. No GPU is assumed: DDP/FSDP/AMP prompts are
graded from the answer text. HEP-ML cases come first because that is the priority workload (2026-10-01).
"Reads" names the reference the skill should send the model to (a signal, not a requirement).
Run: `python3 tests/behavior_eval.py run --model haiku --runs 2 -j 6 --out RUNDIR`, then `score`, then `report`.

## Trigger test (description)

`tests/trigger_queries.json` (tuning set: 20 should-trigger, 20 should-not) and `tests/trigger_queries_holdout.json`
(never tuned on). Run with the sibling harness, from the repository root:

    python3 hep-analysis/tests/routing_eval.py deep-learning/tests/trigger_queries.json --target deep-learning \
        --model haiku --runs 2 -j 4 --out /tmp/dl_routing.json

Near-misses included: TensorFlow/JAX, scikit-learn, generic statistics, `hep-analysis` ROOT work, LLM API usage.
