# deep-learning Examples

Canonical worked examples in one of eight archetypes - see `agile-development`'s
[references/example-authoring.md](../../agile-development/references/example-authoring.md)
for the archetype-selection guide and how these are generated and validated
(requires `agile-development` installed alongside this skill).

| Example | Archetype | Scenario | One-line takeaway |
|---|---|---|---|
| [01-imbalanced-dataloader-training-loop.md](01-imbalanced-dataloader-training-loop.md) | Contrast | A DataLoader and training loop for an imbalanced binary-classification dataset | A DataLoader shuffle and loss tied to the global RNG stream and left unweighted vs. a dedicated generator, class-weighted loss, and a checkpoint that saves seed/RNG state alongside the weights |
| [02-nan-loss-mixed-precision.md](02-nan-loss-mixed-precision.md) | Contrast | Diagnosing a NaN training loss under automatic mixed precision in a Transformer fine-tune | Lowering the learning rate and clipping harder around an unlocated NaN vs. localizing the fp16 softmax overflow inside a hand-written attention module and fixing it with an explicit fp32 block |
| [03-ddp-vs-fsdp-parallelism-choice.md](03-ddp-vs-fsdp-parallelism-choice.md) | Contrast | Choosing a parallelism strategy for fine-tuning a 7B-parameter model that no longer fits under plain DDP | Retrying smaller micro-batches against a DDP OOM vs. computing the four-term memory budget, identifying the optimizer state as binding, and switching to block-granularity FSDP full sharding |
| [04-trajectory-exploding-gradient-nan-after-epoch3.md](04-trajectory-exploding-gradient-nan-after-epoch3.md) | Execution Trajectory | A training run whose loss turns to NaN at the start of epoch 4 with no code changes | A distinct NaN root cause from example 02: an LSTM layer's gradient norm grows unbounded over three full epochs before overflowing, localized with a backward hook, fixed with gradient clipping and LR warmup, and verified by resuming past the failure point |
| [05-trajectory-group-leakage-val-metric-collapse.md](05-trajectory-group-leakage-val-metric-collapse.md) | Execution Trajectory | A 0.98 validation AUC that collapses to 0.71 in a live production A/B test | Traces the gap to row-level random splitting over a dataset with repeated per-customer rows, fixes it with a customer-level group split, and verifies the corrected offline AUC now sits within the normal offline/online gap of the real A/B result |
| [06-trajectory-checkpoint-missing-optimizer-state.md](06-trajectory-checkpoint-missing-optimizer-state.md) | Execution Trajectory | A resumed training run whose loss jumps upward and takes thousands of steps to recover | Traces the jump to a checkpoint function using the inference-only weights pattern instead of the full training-resumable pattern, silently discarding optimizer/scheduler state on every resume; fixes it and verifies a discontinuity-free resume |

| [08-gated-pipeline-ddp-to-fsdp-migration.md](08-gated-pipeline-ddp-to-fsdp-migration.md) | Gated Pipeline | Migrating a growing model's training job from single-node DDP to multi-node FSDP | Three gates - measuring the actual binding memory term before choosing a strategy, a factorization aligned to that measurement, and a red-team pass that finds a silent multi-node metric-aggregation bug before the merge gate |
| [09-gated-pipeline-model-release.md](09-gated-pipeline-model-release.md) | Gated Pipeline | Releasing a new fraud-detection model candidate to replace the current production model | Three gates - a regression suite that surfaces hidden regressions behind an aggregate gain, a full release plan, and a red-team pass that finds both a selection-bias gap and a real training/serving feature-computation skew before the canary gate |
| [10-decision-tree-training-failure-classification.md](10-decision-tree-training-failure-classification.md) | Decision-Tree | A training run whose loss isn't improving, with the failure mode not yet identified | Formalizes this skill's own training-failure classification table into a 5-row matrix, selects the generalization-failure branch for a falling-train/rising-validation-loss case, and defines fallback re-triage against implementation and objective-mismatch causes |

| [12-decision-tree-eval-metric-anomaly.md](12-decision-tree-eval-metric-anomaly.md) | Decision-Tree | A tracked evaluation metric changed unexpectedly after a routine pipeline update | Selects the eval-set-versioning branch for a metric jump after a dedup step, and distinguishes a genuine contamination fix from a newly introduced leak rather than assuming either by default |

| [14-test-first-dataloader-throughput-invariant.md](14-test-first-dataloader-throughput-invariant.md) | Test-First | A DataLoader must sustain >= 500 samples/sec without starving the GPU (util >= 90%) | Red on a single-worker loader (187.3 samples/sec) to green on a tuned num_workers/pin_memory/persistent_workers configuration (612.4 samples/sec, 93% GPU util) |
